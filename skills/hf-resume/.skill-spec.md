# skill-spec: hf-resume

Captured during Phase 0 intake. Seeds authoring and future `skill-doctor` regression tests.

## name
`hf-resume`

Chosen over `hf-download` / `hf-pull` to keep a clean boundary with the installed `hf-cli`
skill (which owns auth / repos / jobs / browsing / `hf` subcommand reference) and to name the
differentiator: resume that actually works.

## description
Download Hugging Face models/datasets with resume that actually works — pinned
`huggingface_hub==1.16.4` run via `uv`, plus a native Swift progress window (overall bar,
speed, ETA, full file list, per-file live progress). Detached daemon: survives window close
and session end.

## should_fire
1. `下载 mlx-community/flux2-klein-9b-8bit 这个模型`
2. `hf download 老是从头开始下，帮我把这个模型下下来`
3. `download Qwen/Qwen3-8B from HuggingFace, show me a progress window`
4. `把这个 HF 模型拉下来，要能续传`
5. `resume that interrupted model download`
6. `这个 17GB 的模型下到一半断了，接着下`

## decoys (must NOT fire)
- `hf auth login 怎么用` → `hf-cli`
- `上传我的模型到 HuggingFace` → `hf-cli`
- `把这个 release tarball 从 URL 下下来` → `filetransfer`
- `帮我找个最好的文生图模型` → `huggingface-best`
- `这个模型要多少显存才能跑` → `hf-mem`
- `本地生成一张图` → `zimage`
- `下载这个 YouTube 视频` → neither

## examples
```bash
hf-resume pull mlx-community/flux2-klein-9b-8bit
hf-resume pull Qwen/Qwen3-8B --include '*.safetensors' --workers 4
hf-resume pull HuggingFaceFW/fineweb --type dataset --local-dir ./fineweb
hf-resume status ; hf-resume window ; hf-resume stop ; hf-resume verify <repo>
```

## needs
- `uv` (present: 0.11.15) — runs `downloader.py` as a PEP-723 script with the pinned lib
- `huggingface_hub==1.16.4` — pinned because it is the last line that still resumes
- `swiftc` (present: 6.3.3, Xcode 26.5) — compiles `Window.swift`, cached by source hash
- No aria2, no `hf_transfer`, no `hf_xet` — all three break correctness here (see SKILL.md)

## functional_test
**Task:** `hf-resume pull mlx-community/flux2-klein-9b-8bit --include 'vae/*'` against a
throwaway `HF_HOME`; kill it mid-flight; run the same command again.

**Success condition (all must hold):**
1. `downloader.log` contains `[resume from N/<size>]` with `N > 0` on the second run — i.e. it
   continued instead of restarting at byte 0 (`--verbose` additionally surfaces the library's
   own `(resume from N/M)` line);
2. final `sha256` of the downloaded file matches the repo's official `lfs_sha256`;
3. `state.json` reports `status: done` and every file `state: done`;
4. the Swift window binary compiles and launches as a real front-most window;
5. the daemon is its own process-group/session leader and keeps downloading after its
   launcher is SIGKILLed; `stop` still terminates it and retains the partial.

Note: a 166 MB target finishes in ~10 s on a good link, too fast to observe an interrupt —
use a ≥1 GB file (e.g. `text_encoder/3.safetensors`, 1.69 GB) when testing resume.

## Session findings this skill encodes (all empirically verified 2026-07-25)
| Finding | Evidence |
|---|---|
| `huggingface_hub` 1.24.0 cannot resume across runs | `file_download.py:1908` random-suffix `.incomplete` + `unlink` in `finally`; `http_get` called with no `resume_size` |
| 1.16.4 does resume | `(resume from 20971520/166156527)`, final sha256 matched |
| Resume lives ONLY on the plain-HTTP branch | 1.16.4 passes `resume_size` to `http_get` but never to `xet_get`; file opened `"ab"` → a leftover partial can get a full Xet reconstruction appended. Hence `HF_HUB_DISABLE_XET=1` is mandatory |
| aria2 `-x8` silently corrupts HF downloads | signed CDN URL pins a byte range: reusing it for another range → `HTTP 403`; preallocated file looks full but has holes |
| `hf-mirror.com` is broken | 308-redirects to `huggingface.co`; breaks hf 1.24 metadata resolution (`Local entry not found`) |
| tqdm `desc` is unusable as a progress key | truncated to 40 chars and taken from CDN `content-disposition` basename; this repo has three distinct `0.safetensors`. Poll the filesystem instead |
| A bare `swiftc` binary CAN own a real window, but not via a SwiftUI Scene holding a model | Verified with `CGWindowListCopyWindowInfo`: SwiftUI `App`+`Window` with only value `@State` → 1 window (900x450). Add a model object the App owns (`@StateObject`/ObservableObject, or `@State`/`@Observable`, ±`@MainActor`, ±Timer, ±NSApp access) → **0 windows**, process alive, main thread idle in a normal event loop, nothing in the unified log. Explicit `NSWindow` + `NSHostingView` as top-level code (compiled WITHOUT `-parse-as-library`) → works, 660x552 |
| `NSApp.setActivationPolicy(.regular)` is mandatory | a non-bundled binary is `.prohibited` and shows no window |
| Detaching needs `os.setsid()`, not `nohup` | `nohup` only ignores SIGHUP; the first build died whenever its launcher's process group was killed. Verified after the fix: daemon is its own session leader and kept downloading after its `uv` parent was SIGKILLed |
